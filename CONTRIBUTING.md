# Contributing to Instrukt Labs projects

This is the default guide for Instrukt Labs repositories that don't have their own. If the repository you're working in has a `CONTRIBUTING.md`, follow that instead. Current project guides:

- [Kiln](https://github.com/instruktlabs/kiln/blob/main/CONTRIBUTING.md)
- [Matter Field](https://github.com/instruktlabs/matter-field/blob/main/CONTRIBUTING.md), including [hardware receipts](https://github.com/instruktlabs/matter-field/blob/main/docs/RECEIPTS.md)
- [Sheepdog Sim](https://github.com/matthew-kissinger/sds/blob/main/CONTRIBUTING.md)
- [Three.js Field Grass](https://github.com/matthew-kissinger/threejs-field-grass/blob/main/CONTRIBUTING.md)

## What helps

- **Bug reports with a small reproduction.** Include the steps, what you expected, what happened, and your OS, browser, GPU and Node version where they matter.
- **Documentation fixes.** Wrong commands, broken links, unclear limits.
- **Small, focused pull requests.** For anything larger, open an issue first so the scope can be agreed before you build it.

## Pull requests

- Keep each pull request to one change.
- Describe the problem, the resulting behavior and the checks you ran. The repository's README lists its test commands.
- Leave out credentials, private paths, local machine state and generated build output.

Contributions are accepted under the license of the repository you contribute to.

## Security

Report suspected vulnerabilities privately, not in public issues. See the [security policy](https://github.com/instruktlabs/.github/blob/main/SECURITY.md).

## Conduct

Participation is covered by the [Code of Conduct](https://github.com/instruktlabs/.github/blob/main/CODE_OF_CONDUCT.md).

## Response times

Instrukt Labs is maintained by one person. Replies come when possible; there's no fixed response time.
