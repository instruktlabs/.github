# Security policy

This is the default security policy for Instrukt Labs repositories that don't publish their own. A repository's own `SECURITY.md` takes precedence, for example [Kiln](https://github.com/instruktlabs/kiln/blob/main/SECURITY.md) and [Matter Field](https://github.com/instruktlabs/matter-field/blob/main/SECURITY.md).

## Report a vulnerability

Email [support@instruktlabs.com](mailto:support@instruktlabs.com) with the subject "Security report: <repository name>". Where a repository has GitHub private vulnerability reporting turned on, you can use that form instead.

Include, where available:

- the affected repository and version or commit;
- steps to reproduce, or a small proof of concept;
- the impact you observed or expect;
- your OS, browser, Node version and GPU, if they matter.

Don't include credentials, private assets or unrelated personal data. Don't post exploit details in public issues, pull requests or discussions. Only test against systems and data you own or have permission to use.

## What to expect

Reports are handled on a best-effort basis by one maintainer; there's no fixed response or resolution time. Fixes target the latest release or the default branch. Older versions don't have separately maintained security branches. Disclosure is coordinated with the reporter once a fix is available.
